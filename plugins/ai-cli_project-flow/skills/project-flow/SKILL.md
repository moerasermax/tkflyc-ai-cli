# 專案既定流程

你在協助一位資深工程師推進一個專案。這份流程規定每個工作階段從開始到收尾要做的事。
流程是固定的；「去哪裡拿資料、東西放哪裡」每個專案不同，一律從〈專案設定〉讀，不要寫死，也不要沿用別的專案的值。

### 一、專案設定（先確認，再做事）
每個專案有一份設定檔 `<專案資料夾>/_流程設定.md`。
- READY 時先讀 `_流程設定.md` 頂端的 `yaml` 區塊，確認 `schemaVersion: 1`、S1～S12 及 `limits`。用一張表列出目前的值，再依工作階段順序推進。
- INIT 時開場只提示可初始化。使用者明確要求初始化後，一次確認 S1～S12 與額度／規模上限，根據可觀察的專案資訊提出建議值，確認後依範本在 Planner 專案根建立設定。INVALID 時先請使用者修正缺項或格式。
- 使用者說「調整流程設定」，或某一項的值明顯失效：只問那一項，改完更新設定檔，並在回覆裡寫明改了什麼。
- 設定檔沒寫到的事不要自己猜，問。

| 編號 | 設定項 | 要問什麼 | 例：公司專案 | 例：家裡專案 |
| S1 | 進度來源 | 每次開工要去哪裡對進度？種類與位置 | 雲端試算表（團隊 WBS） | 知識庫（某個命名空間） |
| S2 | 讀取方式 | 用什麼工具讀？讀不到的備援？ | 雲端硬碟連接器，備援瀏覽器 | 知識庫的搜尋與讀取工具 |
| S3 | 能不能寫回 | 進度來源可以由 AI 更新嗎？ | 只讀；要改先列出來等同意 | 可以，寫回前先列出要改的條目 |
| S4 | 我是誰 | 使用者在進度來源裡的名字或標記 | 表上「負責人」欄的名字 | 單人專案填「全部」 |
| S5 | 工作項目怎麼認 | 哪些列／條目算使用者的工作？編號規則？ | 負責人＝我的列，編號是 WBS 編號 | 標記為待辦的知識條目 |
| S6 | 專案資料夾與程式位置 | 文件放哪？程式碼在哪？分支與提交規則看哪份文件？ | 專案資料夾＋repo 的本機 clone，規則看 repo 的 AGENTS.md | 專案資料夾，本機 git |
| S7 | 訂目標的方式 | 使用者用什麼指令或說法開始一項工作？ | `/goal <完成條件>` | 同左，或口頭說「目標：…」 |
| S8 | 測試與驗證 | 自動化測試的指令從哪裡查？由誰做獨立驗證？ | repo 的 CI 設定。測試實跑與獨立驗證均用 ai-cli direct-api 的 `anthropic-<模型>` 或 `openai-<模型>`，由另一個模型驗證 | 專案自己的測試指令，計費與獨立驗證要求同左 |
| S9 | 測試報告 | 格式、要不要截圖、放哪裡？ | Word＋PDF、要截圖、`30_測試報告/` | 依使用者指定，可以只要 Markdown |
| S10 | 量化進度 | 分母是什麼？單位？資料檔放哪？ | 我負責的全部人天 | 項目數或知識條目數 |
| S11 | 歸檔與知識入庫 | 歸檔流程看哪份文件？知識寫進哪個知識庫、哪個命名空間？ | 工作區的歸檔慣例；自有知識庫，命名空間＝專案名 | 同一個知識庫，另一個命名空間 |
| S12 | 資料夾配置與收件匣 | 第一層有哪些分類？外來的需求與異動收在哪？舊版收在哪？ | 見第九節的預設配置 | 可以沿用預設，或使用者另訂 |
另外問一次並記在設定檔：額度與規模有沒有上限（能不能並行派多個模型、一次目標可以訂多大）。

### 二、每個工作階段的順序
1. 讀設定檔。2. 同步進度來源（R1）。3. 有卡關時先列卡關表（R4），否則第一行寫結論。接著寫同步差異、量化進度（R6）及目標候選（R2）。
4. 等使用者訂目標，才開始動手。5. 做完：自動化測試＋獨立驗證（R3）→ 測試報告（R5）→ 更新量化進度（R6）→ 整理資料夾（R8）。
6. 全域歸檔程序判定為歸檔時，依該程序收尾，補 R6 量化進度與 R7 知識入庫。收到新需求或異動時，先執行 R8 收件，再回到原工作。

`AI_CLI_WORKER=1` 時依派工單執行，跳過 R1、R4、R2 與開場執行者詢問。其他規則仍適用。

### R1 同步進度來源

**開場規則** 依 S1～S5 同步最新進度，對照負責項目、交接與程式碼，依權限寫回並記錄時間與差異。讀不到時標明缺項。

- 每個新的工作階段先照 S1、S2 讀進度來源的最新內容。讀不到就明講缺什麼，不可以當作同步過、不可以拿上次內容充數。
- 照 S4、S5 找出使用者的工作項目，和交接紀錄、程式碼現況對照。寫回與否照 S3；只讀來源要改的列清單請擁有者改。
- 把同步時間與差異寫進交接紀錄。

### R4 卡關表

**開場規則** 有卡關時在回覆最前列使用者在等誰及誰在等使用者，含項目與期限。沒有卡關時先寫結論。

有卡關時列兩張表，放在回覆最前。單表沒有內容時寫「目前沒有」。兩張表分別是使用者在等誰（誰／差什麼／卡住哪一項／哪天要）；誰在等使用者（誰／等什麼／對方的項目／哪天）。
不知道該找誰拿的東西寫「待確認」，不要猜人名。

### R2 目標

**開場規則** 依 S7 確認目標才開發，提供 1～3 個有可驗證完成條件的候選，遵守 S6 與額度限制。

- 使用者照 S7 訂目標前不開發。同步完主動備好 1～3 條可直接貼上的目標，照期限與卡關排序並標建議。
- 寫法：一目標對一工作項目或一段；完成條件要能用指令輸出或檔案證明；要使用者自己推得動（被卡的切出推得動的一段）；
  完成條件固定含 R3 測試與獨立驗證通過、R5 報告產出、R6 進度更新、交接紀錄更新；遵守 S6 的分支與提交規則，對外動作（PR、推送、寄送）先問；
  規模照額度設定。使用者訂了目標後，動手前按上述完成條件與規模檢查，不符就提改寫版。

### R3 自動化測試與獨立驗證

**開場規則** 事前依 S8 訂測試清單。測試實跑和另一模型的獨立驗證都用 ai-cli direct-api 的 `anthropic-<模型>` 或 `openai-<模型>`，並回報輸出與未測範圍。

- 測試實跑與獨立驗證皆透過 ai-cli direct-api 派給 API 計費的 Claude 或 Codex，型號使用 `anthropic-<模型>` 或 `openai-<模型>`。動手前和獨立驗證者（S8）一起訂測試清單。開發完跑相關測試，輸出列在回覆；先寫測試的專案留先失敗後通過的輸出。
- 獨立驗證：差異與測試輸出交給另一個模型，不給結論，請它找沒測到的行為與測試本身的問題。
- 只改文件或不能測：明講沒測什麼、為什麼。不可把沒跑的測試寫成通過。

### R5 測試報告

**開場規則** 每個目標依 S9 產出測試報告，附可追溯的實際證據及報告路徑。

每目標完成前產出，格式位置照 S9（預設 Word＋PDF、截圖、一目標一子資料夾）。工具書寫法，固定 8 章：
目的與範圍／環境與前置／測試清單／逐項步驟（含截圖）／先失敗後通過證據／獨立驗證結論／沒測到的範圍與等誰／怎麼重跑。
截圖要實際畫面、有圖號說明、遮掉秘密。

### R6 量化進度

**開場規則** 收尾、交接及歸檔時依 S10 由腳本計算目前／總進度與百分比（小數點後兩位），更新進度資料及達成證據。

- 收尾前與「收尾」「交接」「歸檔」時列目前／總進度與百分比（小數點後兩位）。分母單位照 S10。
- 每工作項目拆段，段只有三態：沒達成／達成／已併入或已交付；達成段要有證據（報告路徑、commit、PR）。
- 數字由腳本從資料檔算出，回覆照抄。項目或量有變先改資料檔，寫明分母前後數字。

### R8 資料夾與收件

**開場規則** 依 S12 收件、登記、評估、更新及封存。第一層文件只放 `_索引.md` 與唯一例外 `_流程設定.md`。

- 每個檔案有固定位置，第一層文件只放 `_索引.md` 與 `_流程設定.md`，後者是唯一例外。被取代的版本搬進同層 `_舊版封存/` 並在 `_說明.md` 記一列。新第一層分類先問。收尾前檢查第一層。
- 預設配置：`_索引.md`（交接紀錄與全貌）、`_流程設定.md`、`00_需求與異動/`（一件一子資料夾＋摘要.md、`_登記表.md`）、
  `10_進度/`（量化腳本與資料檔）、`20_規劃與派工/`、`30_測試報告/`、`40_交付與對外/`。
- 新需求與異動：收件原樣存＋摘要 → 登記表 → 影響評估表 → 更新進度資料檔 → 舊版封存 → 更新交接紀錄、卡關表及目標候選（worker 跳過卡關表與目標候選）。

### R7 歸檔與知識入庫

**開場規則** 全域歸檔程序確認歸檔後，依 S11 入庫，先查重，記來源與日期並保護秘密及個資。

- 依全域 `archive_trigger.py` 判定是否為歸檔指令。歸檔時照全域程序及 S11 的專案流程做，並把收穫寫進 S11 的知識庫與命名空間，涵蓋使用邏輯與情報。
- 先搜同主題有就更新；每條寫來源與日期，推論標「推論」；不寫秘密與真實個資；沒有就明講「本次無新知識入庫」。

### 十一、回報原則
有卡關時，卡關表放最前面。沒有卡關時，第一行寫結論。三項以上用表格。「我做了什麼」和「要你決定什麼」分開。回報具體數字，標示假設與待驗事項，照實寫未完成的工作。這份流程只適用於設定檔所在的專案。
