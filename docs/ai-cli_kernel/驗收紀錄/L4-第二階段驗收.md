## 未明定細節與尚待確認

- 採事件式 JSONL：created 保存規格要求的授權欄位，intent/result 追加生命周期。ID 帶 run ID 以定位，額外保存遠端 URL 與預設分支同意。預設一小時，僅建立同意、不在 create 執行。
- 預設分支同意綁在 create，run 重新確認目前預設分支。無法查到（含空遠端）就拒絕。push 可以建立新遠端分支；merge 必須已有目標。
- 前置驗證失敗不消耗放行；意圖落盤後不論成功、失敗或中斷都消耗。無法確知副作用的 git 非零結果保守記 unknown；不自動重試，也不自動撤銷／恢復授權。
- 舊鎖採人工對帳，無自動 stale 回收。相容舊的未設定 checkpoint 委任書；明確 off 的手動委任書不額外要求回復點。
- 規格要求一般不帶 force 的 push，因此遠端查詢與推送間不能做到原子舊值比較；其他人的並行快轉可能落在窗口內。未以 force-with-lease 偷換規格。git hooks／全權限配置也沒有被隔離。
- Evidence：上述測試名稱、JSONL 事件／暫存 git 斷言及本地驗證輸出。Confidence：對 Windows 暫存 Git／stub 所覆蓋行為為高；對尚未執行的環境不做成功推定；完整 suite、E2E、CI、真實遠端行為仍待外層確認。
