## 未滿足的硬邊界

**完整工作包三尚不能宣稱通過「kernel 沒有任何路徑寫入 Planner／Knowledge」的絕對解讀。**

- Evidence：既有 `workspace.ts/startCheck` 使用 shell 與使用者環境執行委任書命令；contextCommand 可指向任意第三方程式。develop write worker 也具有與使用者相同的權限。這些執行路徑在前一步即明示未隔離，本步依要求保留。
- 已驗證範圍：kernel 本身沒有私人服務 SDK、遠端寫入 API／MCP 或歸檔回呼；模型／外部資料不能修改固定命令，歸檔介面拒絕額外執行參數，note 只存本機文字。前一步靜態與動態斷言、本步新增介面斷言均釘住這個較窄的保證。
- Confidence：高；任意同權限程式的副作用無法靠其名稱或輸出文字證明不存在。
- 尚待主導者決定：是否將資料讀取改成有明確能力限制的協定，或新增 OS／容器級隔離。這會改變通用 contextCommand／worker 的契約，超出本步授權，沒有偷偷停用命令或加不可靠黑名單。

因此：歸檔功能可驗收；絕對禁止寫入條款仍是 blocker，不以測試全綠掩蓋。

## 規格未明定的選擇

- 純函式接受已讀取快照，避免 RunStore 方法暗含 I/O；匯出名稱加 aiCliKernel 前綴。API 是本機 I/O 外殼，loop 的 git 觀察經 workspace deps。
- 所有非 running 狀態含 awaiting_approval 都是停住；runnerAlive 只有 false 才視為 interrupted。derivedStop 可補停止 state 尚未落盤的窗口。
- archived.json 綁定 journalSeq 與 append-only 放行事件數；後續新事實再次待歸檔。done 不改執行狀態；同一快照重複 done 保留第一份時間與 note。
- 舊日誌／未落盤的當機窗口只能回報未知，不用目前 git 或結束裁決補造歷史。readonly 舊日誌分支為 null；有 git baseline 時保留基準 head。
- commit 清單為按日誌觀察順序去重的已知 run commit（排除基準）；完整 workspace 歷史涵蓋中間 commit。changedFiles 是最後一次觀察相對基準的改動，不是逐次修改聯集。completeCommitList 指最後觀察時的完整性，不涵蓋此後未落盤變化。
- 損毀資料明確拒絕，不將壞標記視為已歸檔，不讓 list／status 靜默漏掉該 run。
- show 預設以完整 JSON 供主 session 閱讀；list 是帶來源的精簡文字或完整 JSON 包。所有字串仍是不可信參考。
