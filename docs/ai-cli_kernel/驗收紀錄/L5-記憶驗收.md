## 不可外推的權限邊界

kernel 沒有實作 Planner／Knowledge 寫入 API 或 MCP 工具。資料與模型提案不能變成 tool 名稱或 contextCommand；contextCommand 只從人提供且核准 digest 綁定的委任書取得。靜態防線與動態拒絕斷言一起涵蓋 CLI、API、MCP、decide、記憶同步與 context 執行路徑。

但規格允許任意命令字串，既有 shell 執行器不是唯讀沙箱，contextCommand 本身仍可能寫本機或遠端。**本步能保證的是 kernel 未提供服務寫入整合，不能保證惡意／設定錯誤的第三方命令永不寫入 Planner／Knowledge。**同權限 develop worker 也不是隔離環境。如果「任何路徑」包括使用者自選外部程式的任意行為，這一要求與一般命令介面存在未解的契約衝突；需主導者決定受限讀取協定／隔離機制，不以名稱或黑名單冒稱防寫。

## 規格未定義的小處與採用依據（尚待確認）

- 人工 add 先 candidate，再顯式 promote；採最小自動啟用原則，避免新增即默默影響規劃。人工文字上限 4000，模型 lessons 上限 500。
- 路徑用 repo 相對前綴、與執行範圍相交；template 為精確比對。未限制路徑時，整個 repo 可參考所有路徑記憶。空字串或 `.` 表示根目錄；不提供 glob。
- origin 使用 git 回傳的 URL 原文雜湊，不做大小寫、尾斜線或協定等價正規化；無 origin 多 root commit 時採 git 反向列表第一筆。
- 模型候選 scope 記 template 與目前可操作路徑；不從模型接受 scope/status/source。沒有 git 身分的舊唯讀用法保留，lessons 只留日誌，無法跨 run 持久參考。
- 記憶殘行拒絕，不仿 run 日誌忽略，因為殘行可能是撤銷。狀態更新追加完整版本，鎖殘留請人對帳。人工可再次 promote revoked；kernel 不會自動做。
- contextCommand 是 1–8000 字元命令字串，於原 workFolder 執行；在既有 checkpoint 後、workspace 前讀一次，避免依賴尚未存在的 worktree。stdout 前綴作資料，stderr 僅失敗證據；checks 原始 log 可能大於 8000，outputs/context.txt 最多 8000。
- context 意圖後中斷即結果不明，不再執行。一般失敗繼續，但取消、未確認程序停止、磁碟落盤失敗仍守住既有安全閘。沒有完整交付報告的 run 由 status/result 顯示 context 診斷。
- 沒有新增記憶 MCP 寫入工具；僅 CLI 的人工操作可啟用記憶。所有輸入依現有 strict schema／範本 digest 慣例處理。
