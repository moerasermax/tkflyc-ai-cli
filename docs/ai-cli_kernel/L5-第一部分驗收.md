# L5 第一部分：委任範本與後續驗收索引

本索引涵蓋 L4–L5 規格「共通規則」及「工作包二」的兩次實作：委任範本，以及本次主動觸發／每日帳本／排程。記憶與歸檔包屬工作包三，不在範圍內。下方原有範本驗收與後續清單保留作前一步紀錄；目前狀態以新增的「主動觸發驗收」為準。

## 實作位置

- `src/ai-cli_kernel/mandates.ts`：四欄持久資料、純函式 digest／狀態、start 輸入驗證與固定預設值、五項操作、期限／人工承認／worker 防線、原子寫入與同名鎖。
- `src/ai-cli_kernel/api.ts`：統一匯出五項範本 API，既有回復點、單次放行、run 核准與啟動不變。
- `src/ai-cli_kernel/cli.ts`：`startInput` 共用解析；`mandate` 子命令的參數、JSON、可讀顯示與錯誤碼。
- `src/ai-cli_kernel/mcp-tools.ts`：只有 `ai-cli_kernel_mandate_list`；沒有範本核准或其他寫入工具。
- `tests/verify-ai-cli_kernel.mjs`：具名區段「L5 第一部分：委任範本（不啟動 run）」。
- `tests/verify-ai-cli_kernel-e2e.mjs`：具名斷言「委任範本 E2E」，跨 CLI 程序持久讀取與 MCP 清單／列表。
- `tools/mutations.json`：22 筆 `kernel mandate：` 突變，from 擷取實際原始碼並驗證只出現一次。

修改前備份在 `docs/ai-cli_kernel/mandates-before.log`（ignore 排除、不交付）；E2E 在修改前補入同一份備份。未 commit、push、切換分支、改 Git 設定或執行 npm test。測試使用既有 sandbox 與暫存 repo，不連真實模型、遠端或排程器。

### 跨步整合與尚待確認

工作包一的 checkpoint 及 release 防線直接重用；本次整合測試從已人工核准的 mandate 經 trigger 入口、原有 approve、假 runner／worker、真實暫存 worktree、kernel 測試／commit，到 report／verdict。成功路徑只推專用回復點；失敗路徑停在 waiting_human，未呼叫 worker，沒有降成本地。範本 save／approve 本身仍不啟動任務。
