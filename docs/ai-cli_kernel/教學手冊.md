# ai-cli_kernel 教學手冊

想查程式碼裡的問題，在 Claude Code 跟 Claude 說一句話就好：

**「用 kernel 查 XXX」**

把 XXX 換成你想查的範圍和問題，例如：

> 用 kernel 查 `src/auth/` 的登入流程，找出可能漏掉權限檢查的地方

它只會讀，不會改你的任何檔案。第一次用要先設定一次，見最下面的「第一次設定」。

想讓它動手改程式，就說：

**「用 kernel 開發 XXX，測試指令是 YYY」**

> 用 kernel 開發 CSV 匯出功能，測試指令是 `npm test`

它會先保存開工前的回復點，再在獨立的分支上改，自己跑測試，測試過了才算完成。有設定 `origin` 時，預設把回復點備份到那裡的專用分支；任務確認單會列出目的地。**不會替你合併或發布開發結果**，要不要收下由你決定。細節見「讓它動手開發」。

需要找回開工前的內容，可以先執行 `ai-cli kernel rollback <run>` 看還原指令。加上 `--apply` 只會建立一份可供檢查的還原分支，不會切換目前目錄或覆蓋你的檔案。你也可以請主對話協助查看並取回需要的內容。

如果只想在這台電腦保存回復點，建立任務時加 `--checkpoint local`。`--checkpoint off` 會省略回復點，只適合你明確核准的手動任務。備份遇到疑似秘密檔名會停下；遠端備份失敗也會停下，手動任務經你再次核准才改成只留本地。

## 開發成果確認後，只放行一次

開發完成後，先看 `ai-cli kernel result <任務編號>` 的報告。確認最新版本正確，才建立一次性的同意：

```text
ai-cli kernel release create <任務編號> --action merge --target <要收下成果的分支> --confirm <報告最新版本的前10碼>
ai-cli kernel release run <上一行回傳的放行編號>
```

第一行只記住你的同意，預設一小時內有效；第二行才真的收下成果。先讓專案目前所在的分支就是你填的目標，並把尚未保存的工作處理好。kernel 不會替你切換位置；如果版本或目標已經變了，也會拒絕。

要把成果送到遠端時，改用 `--action push --target <遠端分支>`，預設送到 `origin`。如果填的是遠端預設分支，還要另外加 `--allow-default-branch`：**這可能等於正式部署**，請看過報告再決定。

放行只能用一次。若顯示 `unknown`，表示無法確定剛才是否已成功，先確認實際結果，不能直接重跑同一個放行。這個同意只接受命令列，由你本人決定；自動觸發的任務不允許建立放行。

## 接下來會發生什麼

1. **Claude 先給你看任務確認單**：要查什麼、看哪個資料夾、最多用多少額度。這時還沒開始。
2. **你說「好」**：內容不對就直接說要改哪裡。
3. **它自己跑**：通常 3～5 分鐘。這段時間可以做別的事，關掉 Claude Code 也沒關係。
4. **Claude 把報告交給你。**

中途遇到額度快用完、資料夾內容被改動，或看不懂目標時，它會停下來問你。

## 報告怎麼看

報告一定有三段：

- **結論**：先看這段。
- **發現**：每個問題都附檔案和行號，程式會實際打開檔案核對。
- **尚待確認**：它沒讀到、沒驗證的部分。

> 核對過的是「引用的位置真的存在」，不是「判斷一定正確」。重要的結論還是要自己看過。

## 怎麼說，結果比較好

講清楚**看哪裡**和**找什麼**。範圍越具體，結果越好，也越省額度。

| 太模糊 | 比較好 |
|---|---|
| 看一下這個專案 | 查 `src/auth/` 的登入流程，有沒有漏掉權限檢查 |
| 有沒有 bug | 查 `src/core/job-store.ts` 當機時會不會遺失資料 |
| 幫我修好 | 找出 X 的根因，並附上行號（它不會改檔） |

## 能做什麼、不能做什麼

| 適合 | 不適合 |
|---|---|
| 找 bug、找漏洞 | 修 bug、改程式 |
| 查某個東西為什麼這樣運作 | 跑測試 |
| 上線前再看一遍 | 一兩句就能回答的小問題（直接問 Claude 比較快） |

另外兩件事要知道：

- **一次只能跑一個任務**，暫停中的也算。
- **它不是安全沙箱。** 它防的是 AI 出錯或假裝做完，防不了有人蓄意破壞，不要拿它處理你不信任的內容。

## 讓它動手開發

開發和查問題的流程一樣，多三件事要知道。

**1. 確認單會多一行「未隔離」，這句要認真看。** 改程式的 AI 權限等於你本人，能動到電腦上的任何東西、也能用你設定好的工具和連線。它被要求只改分支裡的檔案，kernel 事後也會查，但查到時事情已經發生了。所以：

- 只用在你信任的專案。不要拿它處理來路不明的程式碼或文件，那些內容可能夾帶指令。
- 確認單上的範圍、預算和期限都要看過。你同意了，Claude 才會送出那個「我知道未隔離」的確認。

**你的 hook 還在嗎？** 大致上是，但有例外。全域 hook 對改程式的 AI 一樣有效，實測 Codex 想跑 `git reset --hard` 會被擋。專案層的 Codex hook 很可能不生效，確認單會提醒你。kernel 自己跑的指令（測試、commit、清理）則不經過 hook。hook 能防失誤，防不了蓄意，所以上面的「只用在你信任的專案」還是要遵守。

**2. 它怎麼判斷做完了。** 不是聽 AI 說，是 kernel 自己跑你給的測試指令。

| 情況 | 結果 |
|---|---|
| 測試通過 | 交付分支和報告 |
| 測試沒過 | 把錯誤交回去，再改一輪 |
| 改到範圍外的檔案 | 這一步不算數，也不會 commit |
| 測試失敗 4 次，或預算用完 | 停下來，改到一半的東西留在分支上給你看 |

**測試寫得多好，這個判斷就有多可靠。** 測試沒涵蓋到的地方，它照樣會說通過，所以合併前還是要看過改動。

**3. 做完之後要你決定。**

| 想做什麼 | 這樣說 |
|---|---|
| 看改了什麼 | 給我看 kernel 改了什麼 |
| 收下 | 把 kernel 的分支合併進來 |
| 不要了，或合併完了 | 清掉 kernel 這次的 worktree |

清理時，沒合併的分支會留著，不會把你的東西刪掉。

**讓結果更好的說法：**

| 想要 | 這樣說 |
|---|---|
| 限制能改的地方 | 用 kernel 開發 XXX，只能改 `src/export/`，測試指令是 YYY |
| 找另一個模型把關 | 用 kernel 開發 XXX，寫完派 Grok 唯讀審查，測試指令是 YYY |
| 專案要先裝套件 | 用 kernel 開發 XXX，準備指令是 `npm ci`，測試指令是 `npm test` |

新的分支裡沒有 `node_modules` 這類被 git 忽略的東西，專案要先安裝的話一定要給準備指令，不然測試會直接失敗。

開發比查問題貴很多。實測只加一行程式、外加一次審查，就用了約 70 萬 input tokens（大部分是快取）。

## 之後常用的說法

都是直接跟 Claude 說：

| 想做什麼 | 這樣說 |
|---|---|
| 看進度 | kernel 現在怎樣了 |
| 它停下來問你 | 直接回答就好 |
| 不想跑了 | 取消 kernel 的任務 |
| 重開機或當機之後 | 把 kernel 的任務接回來（做過的不會重做） |
| 省一點額度 | 用 kernel 查 XXX，最多跑 20 分鐘 |
| 查仔細一點 | 用 kernel 仔細查 XXX（比較花額度） |
| 看以前查過的 | 列出 kernel 最近的任務 |

遇到看不懂的狀況，就問 Claude「kernel 為什麼停了」。

## 第一次設定

只要做一次，大約 2 分鐘。在 Claude Code 的輸入框依序做：

**1. 開啟工具**（開頭的 `!` 要留著）：

```powershell
! node "<ai-cli 資料夾>\dist\bin\ai-cli.js" kernel enable
```

**2. 重新連線：**

```powershell
/mcp
```

**3. 跟 Claude 說：**

> 幫我跑 kernel 的權限檢查

這會真的叫 AI 試著寫檔，確認有被擋下來，大約 1 分鐘：

| 結果 | 意思 | 怎麼辦 |
|---|---|---|
| `PASS` | 限制有效 | 可以開始用了 |
| `UNKNOWN` | AI 這次沒有全部試完 | 再跑一次 |
| `FAIL` | 限制沒有生效 | **先不要用**，把結果貼給 Claude |

`codex` 更新之後要再跑一次，到時候它會提醒你。目前只有 `codex` 能通過這項檢查。

想用命令列，或想知道裡面怎麼運作，請看[技術手冊](./技術手冊.md)。


## 把常用任務存成委任範本

同一種工作常常要做，可以先存好目標、工作目錄、模型與驗收指令。範本儲存和核准都不會立即開始工作。

```text
ai-cli kernel mandate save daily-audit --goal "檢查程式碼並列出有依據的發現" --cwd .
ai-cli kernel mandate show daily-audit
ai-cli kernel mandate approve daily-audit
ai-cli kernel mandate list
ai-cli kernel mandate revoke daily-audit
```

`save` 可以用建立任務時的選項，例如 `--goal-file` 讀取目標檔案、`--model` 選模型。名稱使用小寫英文字母、數字、底線或連字號，最多 64 字，以英數開頭。

會改程式的 `develop` 範本要提供 `--test` 驗收指令；核准時加上 `--acknowledge-unisolated`，表示你知道工作者權限等於你本人，工作資料夾沒有把權限隔離。先用 `show` 看清楚完整內容，再核准。

人工同意預設 30 天到期，可用 `approve <name> --days 7` 改為 7 天。每次重新 `save`，即使內容相同也要重新核准。`revoke` 只取消同意，仍保留範本方便之後查看或修改。列表會顯示尚未核准、已核准、過期或內容變動的狀態（JSON 分別是 unapproved、approved、expired、changed）。

每日上限預設 1 次、2000000 個未快取輸入 tokens；可在 save 加上 `--max-runs-per-day`、`--max-tokens-per-day` 調整。每日上限已由觸發帳本檢查；設定成 0 會阻止觸發。核准範本不會自行開始任務。MCP 可讀範本列表，範本核准仍須由人使用上述命令。


## 開啟一次觸發，再安排時間

先保存並核准上面的 daily-audit。開關預設關閉；以下先手動試一次：

```text
ai-cli kernel triggers on
ai-cli kernel trigger daily-audit --json
ai-cli kernel status
ai-cli kernel triggers off
```

開啟只代表允許觸發，沒有常駐服務，也不會自己開始。每次 trigger 先檢查總開關、執行身分、範本同意與期限、每日餘額，再看有沒有別的任務正在做；不符合就記錄原因並結束，不排隊、不重試。MCP 的 enable 開關與這個開關分開。工作者不能替你核准範本、開關觸發或套用排程。

JSON 的 started 只表示已啟動，請用回傳的 runId 查 status；結束後用 result 看報告。skipped 代表這次沒跑，例如 triggers_disabled（開關關閉）、mandate_unapproved／mandate_changed／mandate_expired（需檢視或重新核准）、daily_runs_limit／daily_tokens_limit（今天額度用完）、active_run_locked（其他任務佔用）。正常跳過的結束碼是 0，不能只看結束碼判斷開始了沒有。failed 表示記錄或啟動失敗，需人工檢查，結束碼是 1。

每日次數與未快取輸入用量會留下帳本，重開機或重新核准都不會清空。日期按這台電腦的本機日曆日；跨午夜的任務仍算在啟動日。準備啟動就佔一次名額，失敗也不自動退還。量不到用量或中斷結果不明會停止後續觸發，請先用 status／cancel 確認；不要刪帳本當作重試。最後一次模型呼叫可能超出餘額，這個限制不能保證供應商端絕不超支。

要每天 09:00 跑，先看預覽：

```text
ai-cli kernel schedule daily-audit --daily 09:00
```

Windows 確認命令後加 --apply 才會登記名稱為 ai-cli_kernel_daily-audit 的排程；登記本身不會開啟總開關，也不會核准範本：

```text
ai-cli kernel schedule daily-audit --daily 09:00 --apply
ai-cli kernel triggers on
```

改用每隔 3 小時是 --every-hours 3，必須是 1–999 的整數，不能與 --daily 同用。Windows 不會強制覆寫同名工作；要換時間先預覽移除，再明確移除、重新建立：

```text
ai-cli kernel schedule daily-audit --remove
ai-cli kernel schedule daily-audit --remove --apply
```

Linux／macOS 即使加 --apply 也只印出 crontab 的一行，請自行登記；--remove 只提示移除相同名稱標記的行。小時間隔由固定時間基準算起，不表示登記後剛好等 N 小時。排程會指向目前的 Node 與安裝入口；移動安裝位置後請重新預覽並建立。Windows 是否在登出或關機後補跑由作業系統設定決定，本功能沒有補跑機制。

關閉總開關或 revoke 只阻止後續觸發，不會取消已開始的任務，也不會刪除排程。要停當次任務，用 cancel 加上 runId；要停排程，另用上面的 remove。

## 自動修改程式的額外限制

保存 develop 時仍須給 --test；需要準備環境才加 --setup。先閱讀 show 的完整內容，再用 mandate approve 加 --acknowledge-unisolated 明確同意。範本同意預設 30 天，每次任務的工作期限另由 --mandate-hours 控制，預設 24 小時。

自動觸發不接受 --checkpoint off。有 origin 的預設回復點會備份到專用位置，備份推送失敗就停下來，不會派工作者，也不能降成只留本地；先處理原因。沒有 origin 時預設只留本地。Codex 專案層 hook 在新的工作資料夾可能不生效，註記會寫進任務紀錄。

完成後會留下交付分支與報告，請交給熟悉專案的人檢視；不會自動合併或推送交付內容。觸發的任務不能使用 release 單次放行。這些功能仍是未隔離的本機執行，工作者權限等於你本人。


### 讓 kernel 參考你確認過的經驗

在專案資料夾裡執行：

```text
ai-cli kernel memory add --text "修改登入功能後要檢查登出流程"
ai-cli kernel memory list --json
ai-cli kernel memory promote <上面列出的 id>
ai-cli kernel memory revoke <不再適用的 id>
```

新增的經驗先放在候選區；你 promote 後，下次規劃才會看到。模型提出的 lessons 也只進候選，不會自己啟用。撤銷後下一次規劃就不會再參考。可用 `--paths src` 限定適用資料夾、`--template develop` 限定工作種類；這些路徑從專案最外層算起。記憶只是參考，不代表額外授權。

若已有讀取知識庫的唯讀命令，可在 start 或 mandate save 加 `--context-command "你的唯讀命令"`。核准後只讀一次、取前 8000 字元；讀不到也會繼續，原因會列在結果。先確認命令只會讀資料：它用你的電腦權限執行，並沒有隔離或額外的防寫保護。kernel 不會替你寫回 Planner 或 Knowledge。
