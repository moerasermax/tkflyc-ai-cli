# ai-cli_kernel 教學手冊

想查程式碼裡的問題，在 Claude Code 跟 Claude 說一句話就好：

**「用 kernel 查 XXX」**

把 XXX 換成你想查的範圍和問題，例如：

> 用 kernel 查 `src/auth/` 的登入流程，找出可能漏掉權限檢查的地方

它只會讀，不會改你的任何檔案。第一次用要先設定一次，見最下面的「第一次設定」。

想讓它動手改程式，就說：

**「用 kernel 開發 XXX，測試指令是 YYY」**

> 用 kernel 開發 CSV 匯出功能，測試指令是 `npm test`

它會在獨立的分支上改，自己跑測試，測試過了才算完成。**不會合併、不會 push**，要不要收下由你決定。細節見「讓它動手開發」。

## 接下來會發生什麼

1. **Claude 先給你看任務確認單**：要查什麼、看哪個資料夾、最多用多少額度。這時還沒開始。
2. **你說「好」**：內容不對就直接說要改哪裡。
3. **它自己跑**：通常 3～5 分鐘。這段時間可以做別的事，關掉 Claude Code 也沒關係。
4. **Claude 把報告交給你。**

中途遇到額度快用完、資料夾內容被改動，或看不懂目標時，它會停下來問你。

## 報告怎麼看

報告一定有三段：

- **結論**：先看這段。
- **發現**：每個問題都附檔案和行號，程式會實際打開檔案核對。
- **尚待確認**：它沒讀到、沒驗證的部分。

> 核對過的是「引用的位置真的存在」，不是「判斷一定正確」。重要的結論還是要自己看過。

## 怎麼說，結果比較好

講清楚**看哪裡**和**找什麼**。範圍越具體，結果越好，也越省額度。

| 太模糊 | 比較好 |
|---|---|
| 看一下這個專案 | 查 `src/auth/` 的登入流程，有沒有漏掉權限檢查 |
| 有沒有 bug | 查 `src/core/job-store.ts` 當機時會不會遺失資料 |
| 幫我修好 | 找出 X 的根因，並附上行號（它不會改檔） |

## 能做什麼、不能做什麼

| 適合 | 不適合 |
|---|---|
| 找 bug、找漏洞 | 修 bug、改程式 |
| 查某個東西為什麼這樣運作 | 跑測試 |
| 上線前再看一遍 | 一兩句就能回答的小問題（直接問 Claude 比較快） |

另外兩件事要知道：

- **一次只能跑一個任務**，暫停中的也算。
- **它不是安全沙箱。** 它防的是 AI 出錯或假裝做完，防不了有人蓄意破壞，不要拿它處理你不信任的內容。

## 讓它動手開發

開發和查問題的流程一樣，多三件事要知道。

**1. 確認單會多一行「未隔離」，這句要認真看。** 改程式的 AI 權限等於你本人，能動到電腦上的任何東西、也能用你設定好的工具和連線。它被要求只改分支裡的檔案，kernel 事後也會查，但查到時事情已經發生了。所以：

- 只用在你信任的專案。不要拿它處理來路不明的程式碼或文件，那些內容可能夾帶指令。
- 確認單上的範圍、預算和期限都要看過。你同意了，Claude 才會送出那個「我知道未隔離」的確認。

**你的 hook 還在嗎？** 大致上是，但有例外。全域 hook 對改程式的 AI 一樣有效，實測 Codex 想跑 `git reset --hard` 會被擋。專案層的 Codex hook 很可能不生效，確認單會提醒你。kernel 自己跑的指令（測試、commit、清理）則不經過 hook。hook 能防失誤，防不了蓄意，所以上面的「只用在你信任的專案」還是要遵守。

**2. 它怎麼判斷做完了。** 不是聽 AI 說，是 kernel 自己跑你給的測試指令。

| 情況 | 結果 |
|---|---|
| 測試通過 | 交付分支和報告 |
| 測試沒過 | 把錯誤交回去，再改一輪 |
| 改到範圍外的檔案 | 這一步不算數，也不會 commit |
| 測試失敗 4 次，或預算用完 | 停下來，改到一半的東西留在分支上給你看 |

**測試寫得多好，這個判斷就有多可靠。** 測試沒涵蓋到的地方，它照樣會說通過，所以合併前還是要看過改動。

**3. 做完之後要你決定。**

| 想做什麼 | 這樣說 |
|---|---|
| 看改了什麼 | 給我看 kernel 改了什麼 |
| 收下 | 把 kernel 的分支合併進來 |
| 不要了，或合併完了 | 清掉 kernel 這次的 worktree |

清理時，沒合併的分支會留著，不會把你的東西刪掉。

**讓結果更好的說法：**

| 想要 | 這樣說 |
|---|---|
| 限制能改的地方 | 用 kernel 開發 XXX，只能改 `src/export/`，測試指令是 YYY |
| 找另一個模型把關 | 用 kernel 開發 XXX，寫完派 Grok 唯讀審查，測試指令是 YYY |
| 專案要先裝套件 | 用 kernel 開發 XXX，準備指令是 `npm ci`，測試指令是 `npm test` |

新的分支裡沒有 `node_modules` 這類被 git 忽略的東西，專案要先安裝的話一定要給準備指令，不然測試會直接失敗。

開發比查問題貴很多。實測只加一行程式、外加一次審查，就用了約 70 萬 input tokens（大部分是快取）。

## 之後常用的說法

都是直接跟 Claude 說：

| 想做什麼 | 這樣說 |
|---|---|
| 看進度 | kernel 現在怎樣了 |
| 它停下來問你 | 直接回答就好 |
| 不想跑了 | 取消 kernel 的任務 |
| 重開機或當機之後 | 把 kernel 的任務接回來（做過的不會重做） |
| 省一點額度 | 用 kernel 查 XXX，最多跑 20 分鐘 |
| 查仔細一點 | 用 kernel 仔細查 XXX（比較花額度） |
| 看以前查過的 | 列出 kernel 最近的任務 |

遇到看不懂的狀況，就問 Claude「kernel 為什麼停了」。

## 第一次設定

只要做一次，大約 2 分鐘。在 Claude Code 的輸入框依序做：

**1. 開啟工具**（開頭的 `!` 要留著）：

```powershell
! node "<ai-cli 資料夾>\dist\bin\ai-cli.js" kernel enable
```

**2. 重新連線：**

```powershell
/mcp
```

**3. 跟 Claude 說：**

> 幫我跑 kernel 的權限檢查

這會真的叫 AI 試著寫檔，確認有被擋下來，大約 1 分鐘：

| 結果 | 意思 | 怎麼辦 |
|---|---|---|
| `PASS` | 限制有效 | 可以開始用了 |
| `UNKNOWN` | AI 這次沒有全部試完 | 再跑一次 |
| `FAIL` | 限制沒有生效 | **先不要用**，把結果貼給 Claude |

`codex` 更新之後要再跑一次，到時候它會提醒你。目前只有 `codex` 能通過這項檢查。

想用命令列，或想知道裡面怎麼運作，請看[技術手冊](./技術手冊.md)。
