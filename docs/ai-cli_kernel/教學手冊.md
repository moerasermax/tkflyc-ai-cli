# ai-cli_kernel 教學手冊

平常只要在 Claude Code 跟 Claude 說一句話：

| 想做什麼 | 這樣說 |
|---|---|
| 查程式碼裡的問題 | **用 kernel 查** `src/auth/` 的登入流程，有沒有漏掉權限檢查 |
| 讓它動手改程式 | **用 kernel 開發** CSV 匯出，測試指令是 `npm test` |
| 定期自動做 | **每天 3 點用 kernel** 升級套件並跑 `npm test` |

查問題使用工具受限的唯讀模式。開發成果放在獨立分支，收下前不會合併進專案；這不是權限沙箱。worker 權限等於你本人，仍可能動到其他地方，收下前應看報告和改動。曾有使用者的 SessionStart hook 在主目錄寫入 `.planner-id`。

第一次用要先設定一次，見最下面的「第一次設定」。

## 終端機控制面板

在互動終端機執行 `ai-cli kernel dashboard`；Windows Terminal 可用 `ai-cli kernel dashboard --new-tab` 開新分頁（僅此終端機支援）。stdin、stdout 都必須是 TTY，worker 不可開啟，也不能用新分頁繞過。

從 Claude Code 的命令執行介面開分頁時，父行程可以是 pipe；TTY 檢查在新分頁的面板內進行。啟動器返回成功只代表 Windows Terminal 已接受請求。非 Windows Terminal 或找不到 wt.exe 時，會回傳非零並顯示可自行貼上的命令。

| 按鍵 | 用途 |
|---|---|
| ↑／↓、j／k | 選 run |
| PgUp／PgDn | 捲動完整詳情或報告 |
| 1–9 | 選畫面中對應編號的操作，先顯示確認 |
| r、Esc | 開完整報告、返回 |
| t | 確認後切換自動觸發總開關 |
| f、g | 跳到執行中的 run、立即更新 |
| q、Ctrl+C | 離開面板，不取消 run |

每個變更都會列出對象、會發生的事、注意事項、綁定的 commit 和實際指令；只按 `y` 才執行，`n` 或 Esc 取消，其他鍵忽略。視窗放不下全部確認內容時不能按 y，請放大視窗或取消。操作執行中不接受重複操作；此時按 q／Ctrl+C 會等這次操作收尾後離開，不中斷它；結果不明請人工對帳，不要再次放行。確認前後的 run 或 commit 改變會拒絕執行。

頂端顯示更新時間、執行中、自動觸發和待歸檔數量。執行中每 5 秒更新，閒置每 30 秒；失敗保留上次資料並顯示錯誤，不冒充已更新。列表目標只顯示摘要，詳情的目標和報告可完整捲動。寬視窗左右分欄，窄視窗上下排列，太小會提示放大。

**驗證範圍：** 既有 kernel 真實 CLI 只在一台 Windows 用過。此次新增面板使用自動化替身測試，未做真人 TTY／Windows Terminal 互動驗證，Linux／macOS 尚未實跑。

## 接下來會發生什麼

1. **Claude 先給你看任務確認單**：要做什麼、看哪個資料夾、最多用多少額度。這時還沒開始。
2. **你說「好」**：內容不對就直接說要改哪裡。
3. **它自己跑**：查問題通常幾分鐘，開發可能要一兩個小時。這段時間可以做別的事，關掉 Claude Code 也沒關係。
4. **Claude 把報告交給你。**

中途遇到額度快用完、資料夾內容被改動，或看不懂目標時，它會停下來問你。

## 查問題

報告一定有三段：**結論**先看；**發現**每一項都附檔案和行號，程式會實際打開檔案核對；**尚待確認**是它沒讀到、沒驗證的部分。

核對過的是「引用的位置真的存在」，不是「判斷一定正確」。重要的結論還是要自己看過。

講清楚**看哪裡**和**找什麼**，結果最好，也最省額度。「看一下這個專案」太模糊；「查 `src/auth/` 的登入流程有沒有漏掉權限檢查」就很好。

## 讓它動手開發

適合目標講得清楚、**有測試能判定對錯**的工作：修有重現步驟的 bug、升級套件、補測試、機械式重構。

**確認單上的「未隔離」要認真看。** 改程式的 AI 權限等於你本人，能動到電腦上的任何東西，也能用你設定好的工具。所以只用在你信任的專案，不要拿它處理來路不明的程式碼。

**它怎麼判斷做完了？** 不是聽 AI 說，是 kernel 自己跑你給的測試指令：

| 情況 | 結果 |
|---|---|
| 測試通過 | 交付分支和報告 |
| 測試沒過 | 把錯誤交回去，再改一輪 |
| 改到範圍外的檔案 | 這一步不算數，也不會 commit |
| 測試失敗 4 次，或預算用完 | 停下來，改到一半的東西留在分支上給你看 |

測試沒涵蓋到的地方，它照樣會說通過，所以收下前還是要看過改動。

**讓結果更好的說法：**

| 想要 | 這樣說 |
|---|---|
| 限制能改的地方 | 只能改 `src/export/` |
| 找另一個模型把關 | 寫完派 Grok 唯讀審查 |
| 專案要先裝套件 | 準備指令是 `npm ci` |

新分支裡沒有 `node_modules` 這類被 git 忽略的東西，專案要先安裝的話一定要給準備指令，不然測試會直接失敗。

**開工前會自動留回復點。** 它會把目前的狀態（包含還沒 commit 的檔案）存成專用分支，有 GitHub 就推上去，不動你正在用的分支。推不上去就不開工，看起來像秘密的檔案（如 `.env`）也不會推。不想推上去就說「回復點只留本地」。

## 收下成果或反悔

這些是不可逆的動作，所以**要你自己按**。跟 Claude 說，它會把指令準備好，開頭有 `!`，你確認後按 Enter：

| 想做什麼 | 跟 Claude 說 |
|---|---|
| 看改了什麼 | 給我看 kernel 改了什麼 |
| 收下 | 我要把 kernel 的成果合併進來 |
| 推到 GitHub | 我要把 kernel 的成果推上去 |
| 寫壞了要回去 | 我要回到這次開工前的狀態 |
| 不要了，或收下了 | 清掉 kernel 這次的工作目錄 |

每次放行只綁這一個版本，一小時內有效，用過就失效。顯示 `unknown` 表示不確定有沒有成功，先看實際結果，不能重跑。

回到開工前不會蓋掉任何東西，只會多開一條分支讓你檢查。清理時，沒合併的分支會留著。

## 定期自動跑

跟 Claude 說「每天 3 點用 kernel 做 XXX」，Claude 會存成**委任範本**。要真的自動跑，還要你親自做兩件事，所以不會不小心開起來：

1. **核准範本**：30 天後過期，內容一改就失效。
2. **打開總開關並登記排程**：預設是關的。

Claude 會把指令準備好給你。

自動開發一樣只到分支，不會自己合併或 push。每個範本有每日次數和額度上限（預設一天一次）。別的任務在跑時，這次就跳過，不排隊。

**你睡覺時它也會改程式，權限一樣等於你本人**，所以範本的範圍和測試要設好。不想要了就跟 Claude 說「關掉 kernel 的自動觸發」。

自動跑沒有出現在畫面上，所以早上記得問一句「kernel 昨晚跑了什麼」。

## 記住專案的事

跟 Claude 說「請 kernel 記住：這個專案的測試要先跑 XXX」→ 產生候選 → 你確認收下 → 之後開工才會當參考。口頭說「記住」不會直接啟用。

AI 自己想到的經驗只會變成**候選**，要你同意才會生效：跟 Claude 說「kernel 有什麼候選記憶」，再決定收不收。不想要了就說「撤銷這條記憶」。

## 歸檔

kernel 會從已記錄的事實整理歸檔包，包括改檔、測試結果與失敗原因；中途當掉的任務也能整理。你可以自行閱讀，或交給 AI 整理進自己的筆記系統。

標記歸檔只寫本機紀錄，不會寫入外部服務。未標記的任務會留在待歸檔清單，查狀態時就看得到。Planner、Knowledge 是作者自己的選用服務，公開讀者不需要安裝。

## 你的 hook 還有效嗎

大致上有，但有例外：

- **全域 hook** 對改程式的 AI 一樣有效，實測 Codex 想跑 `git reset --hard` 會被擋。
- **專案層的 Codex hook** 很可能不生效，確認單會提醒你。
- **kernel 自己跑的指令**（測試、commit、清理）不經過 hook，確認單上會寫明。

hook 能防失誤，防不了蓄意，所以「只用在你信任的專案」還是要遵守。

## 能做什麼、不能做什麼

| 適合 | 不適合 |
|---|---|
| 找 bug、查原因、上線前審查 | 要你判斷的事：產品方向、架構取捨 |
| 有測試能驗的開發 | 測試驗不到的事：UI 手感、真機、要登入外部服務 |
| 定期的例行工作 | 一兩句就能回答的小問題（直接問 Claude 比較快） |

另外要知道：

- **預設最多同時 3 個任務，同一 repo 1 個**，暫停、中斷、等人仍佔名額，待核准不佔。Claude 週額度剩不到 10% 或量不到時退回全機 1 個；Codex 剩不到 20% 或量不到時，不能同時跑兩個含 Codex 的任務。worktree 與同 origin 的 clone 都算同 repo；被擋立即回錯，不排隊。上限只能由人下調（1～3），MCP 不能改。
- **準備與測試指令全機一次一支**，其他任務會顯示「等測試鎖」；等待可取消，不耗命令逾時及 active wall-clock 預算。
- **重建 dist 前先等其他 run 全部停止**，避免 `version_drift`；本次交付不重建 dist。歸檔先看 list 摘要，再以 show 逐筆讀完整包。
- **它不是安全沙箱。** 不要拿它處理你不信任的內容。
- **目前只在一台 Windows 上驗過；Linux、macOS 尚未實測。**

## 之後常用的說法

| 想做什麼 | 這樣說 |
|---|---|
| 看進度 | kernel 現在怎樣了 |
| 它停下來問你 | 直接回答就好 |
| 不想跑了 | 取消 kernel 的任務 |
| 重開機或當機之後 | 把 kernel 的任務接回來（做過的不會重做） |
| 看以前做過的 | 列出 kernel 最近的任務 |

遇到看不懂的狀況，就問 Claude「kernel 為什麼停了」。

## 第一次設定

前提：Node `^20.19.0 || >=22.12.0`、已安裝並登入 Codex CLI，並已將 ai-cli MCP 註冊到 Claude Code（見 [README 安裝段落](../../README.zh-TW.md#快速開始)）。7.0.0 尚未發佈到 npm；現階段請從 GitHub 取得原始碼，再執行 `npm install`、`npm run build`。

準備好後，在 Claude Code 的輸入框依序做：

**1. 開啟工具**（開頭的 `!` 要留著）：

```powershell
! node "<ai-cli 資料夾>\dist\bin\ai-cli.js" kernel enable
```

**2. 重新連線：**

```powershell
/mcp
```

**3. 跟 Claude 說：**

> 幫我跑 kernel 的權限檢查

這會真的叫 AI 試著寫檔，確認有被擋下來，大約 1 分鐘：

| 結果 | 意思 | 怎麼辦 |
|---|---|---|
| `PASS` | 限制有效 | 可以開始用了 |
| `UNKNOWN` | AI 這次沒有全部試完 | 再跑一次 |
| `FAIL` | 限制沒有生效 | **先不要用查問題的功能**，把結果貼給 Claude |

`codex` 更新之後要再跑一次，到時候它會提醒你。目前只有 `codex` 能通過這項檢查。

想用命令列，或想知道裡面怎麼運作，請看[技術手冊](./技術手冊.md)。
