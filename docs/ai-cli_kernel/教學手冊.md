# ai-cli_kernel 教學手冊

這份手冊帶你從零開始，跑完第一個任務。照著做大約 **5 分鐘**。想知道裡面怎麼運作，請看[技術手冊](./技術手冊.md)。

## 它是什麼

你給它一個目標，它自己規劃、派 AI 去讀程式碼、檢查結果，最後交給你一份**每個引用都核對過**的報告。

和直接叫 AI 做事的差別：

| | 直接叫 AI | ai-cli_kernel |
|---|---|---|
| 誰規劃 | 你或主 session | 它自己 |
| 怎麼算完成 | AI 說做完了 | 程式檢查：引用的檔案和行號要真的存在 |
| 當掉或關掉視窗 | 進度可能不見 | 接回來，做過的步驟不會重做 |
| 花多少錢 | 看 AI 高興 | 事先定好上限，到了就停 |

**第一版只會讀，不會改你的任何檔案。** 適合稽核、查證、找問題。

## 開始前

你需要：

- 這台電腦上已經能用 `codex`
- 一個 PowerShell 視窗

## 第 1 步：設定短指令

指令很長，先設一個短名字 `aik`。這個設定只在目前的 PowerShell 視窗有效，開新視窗要再執行一次。

```powershell
function aik { node "C:\Users\Moera\ai-cli-mcp-source\dist\bin\ai-cli.js" kernel @args }
```

確認有效：

```powershell
aik templates
```

應該看到：

```text
readonly-audit
  唯讀稽核：讀程式碼、列出發現，每項都要附可驗證的 路徑:行號。不改任何檔案。
```

## 第 2 步：跑權限探針

這一步確認 AI 真的改不了你的檔案。它會**真的叫 AI 試著寫檔**，然後檢查有沒有被擋下來。

```powershell
aik probe --agent codex
```

大約 30 秒後應該看到：

```text
探針結果：PASS
四個目標都沒有被建立，而且每一個都有工具層拒絕的紀錄（共 4 筆）
CLI 版本：codex-cli 0.166.0
```

- **同一個 CLI 版本只要跑一次。** `codex` 更新後要再跑一次，它會提醒你。
- 如果看到 `UNKNOWN`，再跑一次就好。AI 有時候沒有全部試完。
- 如果看到 `FAIL`，**先不要繼續**，這代表限制沒有生效。

> 第一版只有 `codex` 能通過探針。`claude`、`grok` 可以跑，但結果最多是 `UNKNOWN`。

## 第 3 步：建立委任書

委任書就是「你要它做什麼、最多花多少」。**這一步還不會開始執行。**

```powershell
aik start --goal "稽核 src/core/worker-env.ts 的防遞迴邏輯：哪些情況會被繞過？" --cwd "C:\Users\Moera\ai-cli-mcp-source"
```

- `--goal`：你要它做什麼
- `--cwd`：它可以讀哪個資料夾

你會看到：

```text
run      kr-20261106-034721-b75c
狀態     等你核准委任書（awaiting_approval）
目標     稽核 src/core/worker-env.ts 的防遞迴邏輯：哪些情況會被繞過？
目錄     C:\Users\Moera\ai-cli-mcp-source
範本     readonly-audit
模型     決策 gpt-6.1-sol（medium）、worker gpt-6.1-sol（medium）
權限     工具受限，非隔離（codex: PASS）
進度     決策 0/5、worker 0/6、input tokens 0/1,500,000、執行 0/90 分鐘
下一步   讀完委任書後，同意就執行 ai-cli kernel approve kr-20261106-034721-b75c，不要就執行 ai-cli kernel cancel kr-20261106-034721-b75c
```

> 畫面上的提示寫 `ai-cli kernel approve ...`。在這份手冊裡，`ai-cli kernel` 就是你剛設的 `aik`。

每一行的意思：

| 欄位 | 意思 |
|---|---|
| `run` | 這個任務的編號，**後面每一步都要用**。把它複製起來 |
| `模型` | 決策和實際讀程式碼的 AI。effort 是思考深度 |
| `權限` | 「工具受限，非隔離」代表 AI 的工具被限制了，但這不是安全沙箱 |
| `進度` | 目前用量和上限，用完就會停 |

## 第 4 步：核准

確認目標和目錄沒寫錯，然後核准。把下面的編號換成你自己的。

```powershell
aik approve kr-20261106-034721-b75c
```

狀態會變成 `執行中（running）`。**從這裡開始它自己跑。你只需要核准這一次，不用一直按 yes。**

只有這些情況它才會回來問你：額度快用完、工作目錄被別人改了、目標不清楚。

## 第 5 步：等它跑完

```powershell
aik wait kr-20261106-034721-b75c
```

這行會一直等到它停下來。一個單檔稽核實測大約 **3 分鐘**。

**你可以關掉這個視窗，甚至關掉 Claude Code，它會繼續跑。** 之後隨時可以回來查：

```powershell
aik status kr-20261106-034721-b75c
```

跑完會看到：

```text
狀態     完成，已通過驗收（completed），原因：delivered
進度     決策 1/5、worker 1/6、input tokens 384,838/1,500,000、執行 3/90 分鐘
步驟
  [通過] p1-s1 稽核 worker 防遞迴及可繞過路徑
驗收     通過
報告     C:\Users\Moera\.local\state\ai-cli\kernel\runs\kr-20261106-034721-b75c\report.md
```

## 第 6 步：看報告

```powershell
aik result kr-20261106-034721-b75c
```

報告一定有三段：

- **結論**：一段話講完
- **發現**：每一項都附 `路徑:行號`。這些引用**程式都打開檔案核對過**，編出來的過不了
- **尚待確認**：它沒讀到、沒驗證的部分

最後一行是裁決，重點看這幾個欄位：

| 欄位 | 看到這個才算好 | 意思 |
|---|---|---|
| `authorization.ok` | `true` | 委任書沒被改過 |
| `execution.ok` | `true` | AI 正常跑完 |
| `delivery.ok` | `true` | 通過所有檢查 |
| `readOnly` | `unchanged` | 工作目錄前後一模一樣 |

> **通過驗收不代表內容一定正確。** 驗收確認的是引用存在、格式完整，不是 AI 的判斷對不對。重要的結論還是要自己看過。

恭喜，你跑完第一個任務了。

## 目標怎麼寫才好

範圍越具體，結果越好，也越省額度。

| 不好 | 為什麼 | 比較好 |
|---|---|---|
| 看一下這個專案 | 沒有範圍，會讀很多檔 | 稽核 `src/auth/` 的登入流程，找出權限檢查的漏洞 |
| 有沒有 bug | 沒說要看哪裡 | 檢查 `src/core/job-store.ts` 當機時會不會遺失資料 |
| 幫我修好 | **第一版不會改檔** | 找出 X 的根因，並附上行號 |

好目標的三個要素：**看哪裡**、**找什麼**、**怎樣算有用**。

## 想控制花費

預設上限夠一般稽核使用。想省一點，或任務比較大，可以在 `start` 加上這些：

| 選項 | 預設 | 意思 |
|---|---|---|
| `--effort medium` | medium | worker 的思考深度，`high` 比較仔細也比較貴 |
| `--max-steps 3` | 6 | 最多派幾個 worker |
| `--max-minutes 30` | 90 | 最多跑幾分鐘 |
| `--max-tokens 500000` | 1500000 | 最多用多少 input tokens |

實際用量參考（Codex gpt-6.1-sol，兩個 job 加總）：

| 任務 | effort | input tokens（多半命中快取） | 時間 |
|---|---|---|---|
| 單檔稽核 | medium | 約 38 萬 | 3 分鐘 |
| 整個目錄稽核 | high | 約 60 萬 | 4～5 分鐘 |

實測：五輪討論、三次這樣的任務和幾次探針加起來，Codex 週額度從 `49% used` 變成 `50% used`（這個數字只到整數位）。

## 它停下來時怎麼辦

先看狀態，**最後一行「下一步」會告訴你該下什麼指令**：

```powershell
aik status kr-20261106-034721-b75c
```

常見狀況：

| 看到 | 意思 | 怎麼做 |
|---|---|---|
| `waiting_human`，原因 `decide_question` | 它看不懂目標，在問你 | `aik approve <run> --note "你的回答"` |
| `waiting_human`，原因 `quota_low` | 週額度剩不到 25% | 要繼續就 `aik approve <run>` |
| `waiting_human`，原因 `quota_unknown` | 查不到額度 | 要繼續就 `aik approve <run>` |
| `waiting_human`，原因 `rate_limited` | 被限流了 | 等一下再 `aik approve <run>` |
| `waiting_human`，原因 `boundary_unverified` | `codex` 更新過了 | 先 `aik probe --agent codex`，再 `aik approve <run>` |
| `waiting_human`，原因 `worktree_changed` | 跑的期間工作目錄被改了 | 用 `git status` 確認是誰改的，沒問題就 `aik approve <run>` |
| `interrupted` | 背景程式不見了（例如重開機） | `aik approve <run>` 接回，做過的不會重做 |
| `version_drift` | ai-cli 被更新了 | `aik approve <run>` 接回 |
| `needs_reconcile` | 當機時分不出某個動作做了沒 | 用 `node ...ai-cli.js jobs` 和 `git status` 確認後，`aik approve <run> --reconcile abandon` |
| `stop_pending` | 取消了，但舊程序還沒確認停止 | 稍等再 `aik cancel <run>` |
| `budget_exhausted` | 預算用完了 | 調高上限，重新 `aik start` |
| `failed` | 連續失敗兩次 | 看「說明」那一行，調整目標後重新 `aik start` |

**想直接放棄：**

```powershell
aik cancel kr-20261106-034721-b75c
```

它會確認背景程序真的停了才回報已取消。

### 常見錯誤訊息

| 訊息 | 意思 | 怎麼做 |
|---|---|---|
| `受治理任務一次只能跑一個，目前被 kr-... 佔用` | 另一個任務還沒結束（暫停中的也算） | 等它跑完，或 `aik cancel kr-...` |
| `codex 的權限邊界探針結果是 UNKNOWN` | 還沒跑過探針，或 CLI 更新過 | `aik probe --agent codex` |
| `模型 xxx 不在候選清單內` | 模型名稱打錯 | 改用正確名稱，或拿掉 `--model` 用預設 |
| `模型 xxx 走 direct-api，它沒有唯讀模式` | 第一版不能用 OpenRouter 這類 API | 改用 `gpt-6.1-sol` |
| `工作目錄不存在` | `--cwd` 打錯 | 確認路徑 |
| `AI_CLI_NESTED_DISPATCH_BLOCKED` | 你在 ai-cli 派出去的 AI 裡面又叫它 | 這是防遞迴，正常不會碰到 |

## 在 Claude Code 裡使用

MCP 工具預設關閉，要先開啟：

```powershell
aik enable
```

然後在 Claude Code 執行 `/mcp` 重新連線。之後直接用說的就好：

> 用 ai-cli_kernel 稽核 src/auth/ 的登入流程，找出權限檢查的漏洞

Claude 會先把委任書給你看，你同意後才開始。會用到的工具：

| 工具 | 用途 |
|---|---|
| `ai-cli_kernel_start` | 建立委任書 |
| `ai-cli_kernel_approve` | 核准或接回 |
| `ai-cli_kernel_status` | 看狀態 |
| `ai-cli_kernel_result` | 看報告 |
| `ai-cli_kernel_cancel` | 取消 |
| `ai-cli_kernel_probe` | 跑探針 |

原生的 `run`、`wait` 等工具完全不受影響。不想要這些工具時，執行 `aik disable`。

## 第一版不能做的事

- **不能改檔、不能跑測試。** 只會讀和回報。
- **一次只能跑一個任務。**
- **只有 `codex` 能通過探針。** 其他家要加 `--allow-unverified`，報告上會標明「未驗證」。
- **不是安全沙箱。** 它防的是 AI 出錯或假裝完成，防不了有人蓄意破壞。不要拿它處理你不信任的內容。
- **一般的 `run` 不受它管。** 只有透過它派的 AI 才算在預算內。
